# 編集・掲載ルール

## 相性で紹介する判断基準

紹介順は広告単価や提携有無ではなく、次を順に比較して決めます。

1. 困りごとへの直接性: その候補が記事の困りごとを直接解決・確認できるか。
2. 利用条件: 対応OS、地域、対象者、料金、登録・契約の要否が読者の条件に合うか。
3. 始めやすさ: 公式ストアから導入でき、初期設定や利用手順が明確か。
4. 情報の確かさ: 提供主体、公式サイト、ストア掲載、更新状況を確認できるか。
5. 注意点: 個人情報、解約、課金、対応範囲、緊急時に代替できない事項を明示できるか。

同じ役割の候補は、用途の違いが読者に分かるよう「向いているケース」と「利用前の注意」を並べます。公的窓口を先に使うべき困りごとは、アプリを無理に上位へ置きません。

## 広告・アフィリエイト

- 広告・提携の有無で通常掲載の順位を変えない。
- アフィリエイトリンクは、案件が承認済みで、対象ページの困りごとと直接関係し、リンク先・条件を確認できた場合だけ付ける。
- 通常リンクをアフィリエイトへ差し替える場合も説明・順位は変えない。
- 「広告」または「PR」を視認できる形で表示し、リンクに `nofollow sponsored` を付ける。
- 未承認、否認、版・商品・提供状態が未確認のリンクは掲載しない。
- 掲載中の提携は [affiliate-status.md](affiliate-status.md) に記録する。

## 標準記事テンプレート

1. タイトル・概要: 困りごとと到達点を明確にする。アプリ名を不自然に詰め込まない。
2. 最初に知っておきたいこと: 緊急性、前提、最初の安全行動を示す。
3. 確認する順番: 読者が実行できる3段階程度の手順。
4. 候補比較: 名称、種別、役立つ点、向くケース、注意点、公式・ストア導線。
5. 補足解説: 検索意図に必要な制度・使い分け・例外を一次情報に基づき説明。
6. 利用前の注意: 課金、契約、個人情報、緊急時の代替不可など。
7. 関連する困りごと: 次の行動に自然につながる内部リンク。
8. 作成・確認方法: 情報源、確認項目、最終確認日。

## 文体・トーン

- 落ち着いた、短く具体的な日本語を使う。読者を責めず、できる順番を示す。
- 断定できないことを断定しない。「必ず」「絶対」「最安」「治る」「得する」は根拠なしに使わない。
- 不安を煽る見出し、過度な緊急感、ランキング根拠のない「おすすめ1位」を避ける。
- 公式名称、対象地域、料金、提供状況は確認日を添え、最新情報はリンク先確認を促す。
- 個別の診断、法律判断、投資・保険商品の推奨は行わない。

## YMYL分野

- 健康・介護: 診断・治療をせず、緊急時は119等を優先。厚生労働省、自治体、医療機関等の一次情報を使う。
- お金・契約: 利益や返金を保証せず、料金・解約・請求期限を公式規約で確認。個別判断は公的窓口・専門家へつなぐ。
- 法律・相談: 一般的な制度と相談準備に限定し、個別具体的な法的助言はしない。
- 子ども・DV・メンタルヘルス: 安全を優先し、閲覧履歴や連絡方法にも配慮した表現を使う。

## 最終確認日

`reviewedAt` / `updated` は、掲載する全候補の公式サイト・ストアと重要な制度情報を実際に再確認した日にだけ更新します。文言修正だけでは更新しません。90日以上経過した記事は月曜点検で要再確認とし、確認結果をコミットまたは運用記録に残します。
