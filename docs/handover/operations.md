# 日常運用

認証情報はこの文書に記録しません。操作前にログイン中のアカウントと対象サイトを確認します。

## X投稿（週次の下書き作成）

- 目的: 公開中の記事から、生活上の困りごとと役立つアプリを1日1件伝える。
- 体制: Claudeは毎週1回、翌週7日分の投稿文を作る。利用者がXの予約投稿に登録する（Claudeは`@kotonaviapp`にログインしない）。
- 投稿時刻の目安: 毎日8:00（日本時間）。
- 下書きの作り方: (1) [x-post-log.md](x-post-log.md) で過去の投稿と重複確認、(2) 公開中の記事を7件選ぶ（同じアプリ・同じ切り口を避ける）、(3) 外部リンク監視で異常がない記事だけを選ぶ、(4) 「よくある困りごと→アプリと役立つ点→該当記事URL」で1件ずつ作る、(5) 広告案件を含む記事は広告と明示、(6) URL込みで280文字（日本語は140字相当）以内を確認。
- ハッシュタグ: 必要な場合だけ0〜2個。無関係なトレンドタグは使わない。
- 記録: 下書き作成時に、投稿予定日・本文・記事URLを [x-post-log.md](x-post-log.md) に「予定」として追記する。公開URLは分かれば後から追記する。

## 外部リンク監視

- 目的: 読者をリンク切れ・終了サービスへ案内しない。
- 頻度: 毎週月曜6:00（日本時間）にGitHub Actions `.github/workflows/link-check.yml` が自動実行。手動実行も可（workflow_dispatch）。
- 方法: `scripts/check-links.mjs` が `app/` 配下のソースから外部URLを抽出してHTTP状態を確認する。Claudeの作業環境は多くの外部サイトへ接続できないため、Actions上で実行する。
- 判断基準: 404・410・5xx・接続失敗は「要対応」。403・429などはボット対策の可能性があるため「目視確認」とし、リンク切れと断定しない。
- 結果: 要対応があればIssue「外部リンク監視: 要対応」を作成・更新し、解消すれば自動で閉じる。各回の全結果はActionsの実行サマリーに残る。
- 対応: 異常リンクを使う記事はX投稿の対象から外す。サイトは自動修正せず、公式情報を確認してからPRで直す。

## 月曜日の本番・SEO点検

- 目的: 配信、インデックス、鮮度、検索流入の異常を早期発見する。
- 頻度: 毎週月曜日。
- チェックリスト:
  1. `https://kotonaviapp.com/`、`/robots.txt`、`/sitemap.xml` が200。
  2. sitemap掲載URLが200で、本番に意図しない`noindex`がない。
  3. `www`から正規ホストへ308、`/neko`から`/neko/`へ308。
  4. ステージングの全応答に`x-robots-tag: noindex, nofollow, noarchive`。
  5. 全外部リンクの状態と異常リダイレクト。
  6. `reviewedAt` / `updated` が90日以上前の記事を抽出。
  7. Search Consoleで過去7日・28日のクリック、表示回数、CTR、平均掲載順位、インデックス登録、クロール・ページエラー、クエリ/ページ別の急変を確認。
- 判断基準: 本番noindex、sitemapの404、重大な減少、クロール障害は優先報告。季節性や少量データを原因と断定しない。
- 完了条件: 異常、影響URL、再現方法、推奨対応が整理される。
- 記録先: 定期実行タスク。Search Consoleのプロパティ名・保存先は不明。

## 金曜日の新規テーマ調査

- 目的: 未掲載で、アプリが具体的な次の一歩になる生活課題を見つける。
- 頻度: 毎週金曜日。
- 手順: (1) `content-status.md`とサイト内検索で重複確認、(2) 検索候補・関連質問・公的資料から困りごとの表現を収集、(3) 候補アプリの公式サイト・両ストアを確認、(4) 検索語句案、候補名、OS、役立つ点、注意点、既存記事との差を記録、(5) 20〜30件を優先度付きで報告。
- 採用基準: 生活上の具体的な困りごと、スマホアプリで行動を前進できる、公式情報で確認できる、既存記事と検索意図が重複しない。検索ボリュームは確認できたツール値以外を断定しない。
- 除外: アプリと関係が薄い、提供元不明、ストア未確認、危険な自己判断を促す、個別の法律・医療・金融判断が必要。
- 完了条件: 追加候補と既存記事の更新候補を分けて報告。自動公開しない。
- 記録先: 定期実行タスク。採用後は `content-status.md`。

## アフィリエイト承認確認

- 目的: 承認済みで有効な案件だけを、関連するページに透明性をもって掲載する。
- 頻度: 毎週1回、またはASP通知受信時。
- 手順: [affiliate-status.md](affiliate-status.md) の各ASPで、提携中・申請中・否認・終了を確認し、現行コードと突合。承認後も遷移先、商品・サービス、条件を確認する。
- 判断基準: 承認済みかつ記事との関連性が高い場合のみ掲載候補。順位は変えない。案件終了・否認・不一致は非掲載。
- 完了条件: 状態、確認日、使用記事、必要対応を更新。
- 記録先: [affiliate-status.md](affiliate-status.md)。
